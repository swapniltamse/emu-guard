emu-guard

AWS on your laptop in 10 minutes, Windows included

Give your coding agent a fake AWS, not your real one. emu-guard is a small PowerShell and bash script around AWS Emulator, the local AWS stand-in that AWS released in September 2026.

Quick version

  • 01One command starts AWS Emulator in Docker on Windows, macOS and Linux, listening on your own machine only.
  • 02Before your tests start, emu-guard checks that AWS calls reach the emulator's fake account, 000000000000. If they do not, nothing runs.
  • 03Your tests and your coding agent get no path to your real AWS account. The escape test checks that claim.
macOS and Linux
./emu up
./emu run -- npm test
./emu down
Windows
.\emu.cmd up
.\emu.cmd run -- npm test
.\emu.cmd down

Replace npm test with pytest, go test or any other command.

Step-by-step setup

On Windows, type .\emu.cmd where a step says ./emu. Tested on Windows 11 with Docker Desktop. The bash script is written for macOS and Linux but not yet run there.

  1. Install Docker Desktop, or Docker Engine on Linux.

  2. Start Docker and wait until it is running.

  3. Install the AWS CLI if you want it. Optional

    Without the AWS CLI, emu-guard signs the account check request with curl.

  4. Clone the emu-guard repository.

    Terminal
    git clone https://github.com/swapniltamse/emu-guard

  5. Open the emu-guard folder.

    Terminal
    cd emu-guard

  6. Start the emulator.

    Terminal
    ./emu up

    The first start builds the emulator image for your CPU, x86 or Arm. The emulator listens on 127.0.0.1:9297 only, with telemetry off. emu up waits until the health check passes.

  7. Run your tests through emu run.

    Terminal
    ./emu run -- npm test

  8. Stop the emulator when you finish.

    Terminal
    ./emu down

    Everything you created in the emulator is deleted. The emulator also stops by itself after two idle hours.

What emu run checks before your tests start

Each check runs in this order. If a check fails, your command never starts.

  1. 1RefusesReal key variables in your shell: AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_SESSION_TOKEN or AWS_SECURITY_TOKEN.exit 5
  2. 2RefusesA .env file in the folder that sets a real-looking AWS key, because dotenv would load it after the guard.exit 5
  3. 3RemovesVariables that pull in real credentials another way, such as AWS_PROFILE and AWS_ROLE_ARN, for this run only.
  4. 4SetsThe eight variables from the AWS docs, plus the certificate setting your language needs.
  5. 5RefusesAn AWS SDK that ignores AWS_ENDPOINT_URL: JavaScript v2, Java 1.x or Go v1. For Python, it asks boto3 which endpoint it would use.exit 7
  6. 6ChecksThat sts get-caller-identity answers with account 000000000000.exit 4
  7. 7RunsYour command. Your own shell stays exactly as it was.

Use emu run --strip to drop real key variables for one run instead of refusing.

The account check passed, and the SDK still pointed at real AWS

Verified on a real project, November 13, 2026

A Node project used the JavaScript aws-sdk v2. Under emu run, the account check passed. The SDK still built its DynamoDB endpoint for real AWS:

emu: Guard passed: AWS calls go to https://127.0.0.1:9297 (account 000000000000).
aws-sdk 2.1692.0
DynamoDB endpoint under emu run: https://dynamodb.us-east-1.amazonaws.com/
AWS_ENDPOINT_URL in env: https://127.0.0.1:9297
Why it happenedSDK v2 ignores AWS_ENDPOINT_URL, as the AWS SDK reference guide lists. The account check proves where the AWS CLI goes, not where your SDK goes.
What emu run does nowIt finds SDKs that ignore the variable and stops with exit code 7 before your tests start. Java 1.x and Go v1 are blocked the same way.

If your code passes the endpoint to each client itself, add --allow-old-sdk.

What it stops, and what it does not

It stops

  • Tests that run in a shell with real AWS keys in the environment.
  • Tests that run when the emulator is down or the endpoint is not set.
  • Profiles, SSO, assumed roles and container credentials leaking in through environment variables.
  • A coding agent reading ~/.aws, because emu agent does not mount it.
  • A coding agent changing git metadata to plant a hook. Every .git is mounted read-only.
  • An agent finding AWS keys left in the project or its git history. emu agent refuses to start.

It does not stop

  • Code you run with emu run that opens ~/.aws/credentials by path. For code you do not trust, use emu agent.
  • Changes the agent makes that you run later. Review its diff first.
  • Secrets that are not AWS keys, such as a database password in .env.
  • Data leaving through the network. The agent container has internet access.
  • Emulator gaps. Unsupported operations return HTTP 501 NotImplemented.

AWS says the emulator is not a tool for testing security controls. The real fix is still to keep long-lived production keys off laptops and give each key the least access it needs.
